# ONE MORE FLOOR v1.47 — Actor Production Pipeline

v1.47 builds on the complete five-realm 3D tower and v1.46 production vertical slice. The focus is the actor layer: make the game visibly stronger now with richer native fallback silhouettes while also defining a production contract that real rigged GLB/GLTF characters can enter later without another combat rewrite.

## What changes

- `world3d_model_registry_v147.gd` adds production profiles, animation aliases, socket discovery and model QA reporting.
- `world3d_actor_factory_v147.gd` creates a stable `ProductionSockets` contract for every actor and upgrades the current native Wanderer/enemy art.
- `world3d_chamber_v147.gd` swaps the full tower to the v1.47 factory and adds a fixed-pool Wanderer weapon arc trail.
- `main_v60.gd` keeps production 3D active for floors 1–50.

## Model contract

Seven actor kinds remain registered:

- Wanderer
- Goblin
- Bat
- Skeleton
- Ghoul
- Necromancer
- Warden

The expected production model slots remain `assets/models/actors/<kind>.glb`. Missing files keep using native fallback art. No fake binary model is bundled.

A production-ready imported model is expected to provide visible mesh geometry, a `Skeleton3D`, an animation driver (`AnimationPlayer` or `AnimationTree`) and the required core animation states.

Core states:

- idle
- run
- attack

Extended states:

- hit
- skill
- spawn
- death

The registry resolves common clip aliases and reports model readiness without changing gameplay behavior.

## Stable production sockets

Every player/enemy actor now owns a `ProductionSockets` node with stable logical attachment points:

- WeaponSocket
- OffhandSocket
- HeadSocket
- ChestSocket
- FeetSocket
- OverheadSocket
- VFXSocket

When an imported model has a compatible socket/bone node, the runtime socket follows it. If a target is missing, the socket remains at a safe actor-local fallback position. This keeps VFX/equipment integration resilient while art assets are swapped model-by-model.

## Native fallback art upgrade

The repo still needs to look better before external character assets arrive, so v1.47 adds visible secondary detail to the existing procedural actor silhouettes.

### Wanderer

- hood brow trim
- layered collar armor
- hip satchel and clasp
- back scabbard
- shoulder gem
- purple/gold weapon core detail
- subtle secondary motion for equipment and emissive accents

### Enemies

- Goblin: scrap shoulder plate, loot pouch and buckler
- Bat: wing claws and chest core
- Skeleton: shield and jaw guard
- Ghoul: chain/claw details and rib plate
- Necromancer: floating spell focus, rune motes and robe sigil
- Warden: helm horns, shoulder blades, cape, chest sigil and weapon edge glow

These additions remain mobile-conscious primitive meshes and automatically disappear when a real imported model is active.

## Spawn and animation state handling

Newly occupied enemy proxy slots queue a short `spawn` presentation state. Imported rigs can consume a Spawn animation when available; native actors receive a lightweight scale/rise treatment. The same one-shot contract is ready for hit/death/skill use without moving gameplay authority into the presentation layer.

## Weapon presentation

The Wanderer now has a seven-segment fixed pool for a short weapon arc. It samples the production weapon socket during attack/skill presentation and creates a lightweight real-3D trail without per-frame mesh allocation.

## Kept unchanged

- combat math
- enemy AI
- gameplay collisions
- XP/rewards/economy
- save data
- progression
- touch controls
- 2D HUD and menu authority
- floors 1–50 production 3D coverage
- v1.46 realm transitions, telegraphs, boss framing, death feedback and loot presentation

## Mobile discipline

The pass keeps the existing mobile rules: one main shadow caster, no volumetric GI, fixed pools for transient presentation, no gameplay physics migration, no per-frame mesh creation, and StandardMaterial3D/emissive primitives as the fallback baseline.

## Next production step

Once real rigged model files are supplied, they can be dropped into the documented actor slots and validated against the v1.47 contract. The next code/art pass can then focus on per-character animation tuning, weapon attachments, model LOD/import tuning, material polish and character-specific VFX instead of rebuilding the runtime bridge again.
